#О проекте
SaaS-сервис по бизнес-аналитике Visionary. Платформа собирает метрики, выявляет проблемы, рассчитывает точки роста и предоставляет предиктивную и предписательную аналитику (data-driven подход).

Используй другие правила в проекте для качественного написания кода.
ВАЖНО: При отображении любых данных (даты, деньги, проценты, телефоны) СТРОГО используй функции-хелперы из `@/utils/formatters.ts`. Не хардкодь форматы.

#Общие правила
1. **База данных**: ID записей всегда задаются в формате UUID v4 (в БД по умолчанию `gen_random_uuid()`). Каждая таблица должна иметь колонки `created_at` и `updated_at` с временной зоной (`timestamptz`).
2. **Валюта**: Российский рубль (₽). Форматировать с разделителем тысяч с помощью `formatCurrencyRUB`.
3. **Форматы дат и времени**: Дата — `ДД.ММ.ГГГГ` (ru-RU). Время — 24-часовой формат `ЧЧ:ММ`. Использовать хелперы `formatDate` и `formatTime24`.
4. **Округление**: Для нецелых чисел по умолчанию использовать округление до десятых (в процентах) или сотых (в финансах, копейки).
5. **Адаптивность (Mobile First)**: Верстка должна идеально смотреться на мобильных устройствах. Использовать брейкпоинты `@media (max-width: 768px)` для планшетов и `@media (max-width: 425px)` для мобильных телефонов с комфортными тач-зонами (минимум 44x44px для интерактивных элементов).

Проект построен СТРОГО на **Next.js 15 (App Router) + TypeScript + Tailwind CSS v4**. Это **Next.js-проект**, а не стандартный React-клиент. Вся структура страниц, маршрутизация, метаданные и рендеринг должны полностью соответствовать стандартам Next.js App Router!
Все исходные файлы находятся в папке `src/`:
- `src/app` — маршруты Next.js. Используются Route Groups: `(auth)/` для авторизации, `(main)/` для рабочих страниц с полным layout. Страницы (`page.tsx`) — тонкие клиенты, импортируют View-компоненты. API-эндпоинты (`route.ts`) — бэкенд-логика в `src/app/api/`.
- `src/components` — UI-компоненты, организованные по подпапкам: `ui/` (базовые переиспользуемые), `layout/` (Sidebar, Header, Footer, PageHeader), `dashboard/`, `analytics/`, `organization/`, `profile/`, `plan-fact/`, `billing/`, `support/`, `shared/` (UnderConstruction, SearchView, NotificationsView).
- `src/services` — сервисный слой, организованный по доменным папкам: `analytics/`, `indicators/`, `plan-fact/`, `organization/`, `billing/`, `notifications/`, `calculation-engine/`. Все методы сервисов должны возвращать Promise (быть асинхронными).
- `src/hooks` — глобальные React-хуки (например, `useAnalytics.ts`).
- `src/stores` — Zustand-сторы для глобального состояния (например, `useUIStore.ts`).
- `src/context` — React Context (для провайдеров, например `AnalyticsContext.tsx`).
- `src/types` — строгие интерфейсы и типы TypeScript. Использование `any` строго запрещено.
- `src/utils` — утилитарные хелперы и функции форматирования (`formatters.ts`, `validators.ts`, `constants.ts`).
- `src/lib` — инфраструктурные утилиты (`utils.ts` — cn(), `supabase/` — клиенты БД).
- `src/mock-data` — моковые данные для разработки (временно, до подключения Supabase).
- Все импорты используют алиас `@/` (разрешается в `src/`). Относительные импорты `../` запрещены.

# Code Quality & TypeScript
- **Строгая типизация**: Никаких `any`. Все типы данных должны быть детально описаны. Если тип используется в нескольких файлах, выноси его в `src/types`.
- **Интерфейсы компонентов**: Пропсы должны описываться как `[ComponentName]Props`.
- **Деструктуризация**: Всегда деструктурируй props при объявлении компонента.
- **Паттерн раннего возврата (Early Return)**: Избегай глубокой вложенности условий, используй Guard Clauses для быстрого выхода из функции.
- **DRY (Don't Repeat Yourself)**: Выноси дублирующуюся логику в хуки или утилиты.
- **Комментарии**: Пиши JSDoc только для сложной бизнес-логики (расчет метрик, формулы). Не пиши банальные комментарии вроде "компонент кнопки".

# Next.js & State Management
- **Next.js Роутинг & Рендеринг**: Структура проекта полностью определяется Next.js. Для интерактивных клиентских компонентов ВСЕГДА используй директиву `'use client'` в начале файла.
- **Управление состоянием сервера**: Для работы с Supabase и внешними API используй `TanStack Query` (React Query) с кэшированием и автоматическим обновлением, избегай `useEffect` для запросов.
- **Формы**: Для сложных форм ввода используй `React Hook Form` в связке с `Zod` для валидации данных на клиенте.
- **Кастомные хуки**: Выноси расчеты и стейт из UI-представлений в хуки (например, хук `useAnalytics` управляет состоянием загрузки и вызовом методов `AnalyticsService`).
- **Глобальный стейт**: Для глобальных UI-состояний (авторизация, тема, выбранная организация) используй **Zustand**. Локальное состояние (открытые модальные окна, табы) держи в `useState`.

# База данных и Supabase
- **Именование**: `snake_case` для таблиц, колонок и процедур в БД. В TypeScript-коде используй `camelCase` (мапь данные при получении, если типы не сгенерированы автоматически).
- **Безопасность (RLS)**: Row Level Security обязательна для всех таблиц. У каждого пользователя должен быть доступ только к данным его организации или профиля.
- **Оптимизация**: Выбирай только нужные колонки в запросах (например, `.select('id, name')`), используй пагинацию.
- **Транзакции**: Финансовые операции (списание баланса, смена тарифа) должны выполняться атомарно через RPC (Stored Procedures) в Supabase.
- **Soft Delete**: Не удаляй записи физически. Используй флаг удаленного элемента или статус `is_active: false`.

# Мобильный UX
- **Touch Targets**: Интерактивные зоны от 44x44px.
- **Input Fields**: Для ввода чисел использовать `inputMode="decimal"` и маски для телефонов.
- **Нижние шторки (Bottom Sheets / Drawers)**: Для фильтров и длинных списков на мобильных экранах используй шторки вместо центрированных модальных окон.

# Design System (Tailwind CSS v4)
Проект использует Tailwind CSS v4 с CSS-первым конфигурированием. Все базовые стили импортируются в `@/app/globals.css`. Настройки тем и переменных задаются с помощью стандартных классов или через директиву `@theme` в CSS.

- **Фирменные цвета и Оформление**:
  - **СТРОГО ЗАПРЕЩЕНО** хардкодить конкретные фирменные цвета в правилах. Фирменный цвет бренда будет задаваться динамически.
  - При создании и изменении компонентов **всегда анализируй существующий код соседних файлов в репозитории** и наследуй используемые там классы Tailwind или CSS-переменные (например, `--color-*`).
  - Текстовые стили: основные заголовки — `font-bold`/`font-extrabold`, основной текст — читаемый, приглушенный / подписи — приглушенные (согласно дизайну в коде).
  - Статусы (Успех/Рост/Предупреждения): использовать стандартные семантические индикаторы в соответствии с общим дизайном проекта (зеленый/красный/желтый).
- **Компоненты**:
  - Карточки, поля ввода, кнопки и другие интерактивные элементы должны в точности копировать дизайн-паттерны, скругления, тени и hover-эффекты из уже существующих компонентов в репозитории.

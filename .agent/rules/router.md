# 🧭 Маршрутизатор ИИ-агента (Agent Skill Router)

Этот файл — главный управляющий узел. Он всегда в контексте.

## 🗺️ Как использовать навыки (Skills)

Все специализированные знания, инструкции и промпты для виртуальных сотрудников находятся в папке `.agent/skills/`.

**ВНИМАНИЕ:** Запрещено сканировать все файлы подряд! Используй инструмент `view_file` для загрузки ТОЛЬКО 1-2 файлов, которые прямо относятся к текущей задаче.

### 1. Виртуальные сотрудники (Агенты)
Если задача требует глубокого бизнес-анализа, стратегического планирования или мозгового штурма, вызови нужного агента (открой его файл):
- **`agent-cfo/SKILL.md`** — Финансовый директор (монетизация, Unit-экономика, P&L, тарифы).
- **`agent-cmo/SKILL.md`** — Директор по маркетингу (воронки, позиционирование, конверсия).
- **`agent-cpo/SKILL.md`** — Продакт-менеджер (JTBD, UX, Retention, приоритизация).
- **`agent-founder/SKILL.md`** — Основатель (стратегия, PMF, долгосрочные решения).
- **`agent-cto/SKILL.md`** — Технический директор (архитектура, стек, производительность, БД).
- **`agent-council/SKILL.md`** — Совет директоров (запускает воркфлоу-совещания нескольких агентов: `council discuss` или `council build`).


### 2. Технические навыки
Для выполнения конкретных задач по разработке, ищи подходящий файл в папке `.agent/skills/`. В ней лежат папки по смыслу задачи. Например:
- Для дизайна и верстки ищи папки вроде: `ui`, `designer`, `adaptive-design`
- Для логики: `supabase`, `business-metrics`, `product-analytics`, `financial-analytics`
- Для специфичных фич: `auth`, `rbac`, `notifications`, `quiz`, `onboarding`, `realtime` и т.д.

Открывай только тот `SKILL.md`, который напрямую связан с запросом.

## 🛠️ Алгоритм действий перед написанием кода

1. **Определить контекст**: Понять задачу и открыть 1-2 релевантных навыка из папки `.agent/skills/`.
2. **Форматы**: При работе с деньгами или датами обязательно прочесть `rules/formatting-data.md`.
3. **План**: Составить план решения на русском языке для пользователя.
4. **Важные правила самопроверки**:
   - **Никакого `any`**: TypeScript типы должны быть строгими.
   - **Совместимость Next.js**: Интерактивные компоненты (стейт, хуки) должны начинаться с `'use client'`.
   - **Адаптивность**: Учитывай мобильные устройства (см. `rules/rules.md`).
   - **Сохранение дизайна**: Не ломай текущую верстку без прямой необходимости.

# Каскад: Полный цикл (Discuss ➡️ Plan ➡️ Build)

**Триггеры для запуска:** «совещание и разработка», «council build», «обсудите и сделайте»

Этот workflow предназначен для реализации задачи "под ключ": от бизнес-оценки топ-менеджерами до написания готового кода.

## Механика работы ИИ-агента (Каскад)
При запуске этого воркфлоу, ИИ-ассистент должен выполнить 3 последовательных этапа в рамках ответа/сессии:

### Этап 1: Мини-совещание (Review)
ИИ-ассистент кратко оценивает задачу с четырех сторон, чтобы собрать бизнес и технические ограничения ПЕРЕД написанием кода:
- **CPO**: требования к UI/UX и какие компоненты затронет.
- **CMO**: требования к интерфейсным текстам и онбордингу.
- **CFO**: требования к монетизации (например, скрыть фичу за paywall или как это отразить в тарифах).
- **CTO**: техническая реализуемость, влияние на производительность, изменения в БД (миграции) и архитектурные решения.

### Этап 2: Создание плана (Planning)
На основе собранных ограничений, ИИ-ассистент генерирует артефакт `implementation_plan.md` (на русском языке). План должен содержать:
- Архитектуру и компоненты, которые будут созданы или изменены.
- Бизнес-логику, выработанную на Этапе 1.
- Пошаговый план по написанию кода.

### Этап 3: Написание кода (Execution)
**Сразу после** создания плана (не дожидаясь дополнительных команд пользователя, если не требуются критические уточнения), ИИ-ассистент начинает применять инструменты кодинга (`write_to_file`, `multi_replace_file_content`), чтобы реализовать план шаг за шагом.
ИИ сообщает пользователю о том, какой шаг плана сейчас выполняется.

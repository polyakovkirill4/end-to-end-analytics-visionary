# Разработка интерактивных электронных таблиц (Google Sheets Clone)

Этот навык определяет архитектурные принципы, стандарты верстки, управления состоянием и интеграции с базой данных при создании интерактивных электронных таблиц (Data Grid).

---

## 1. Архитектура рендеринга и производительность (Performance)

При отображении таблиц с сотнями строк и десятками колонок стандартный рендеринг DOM приводит к фатальному падению FPS. Обязательно соблюдение следующих принципов:

### 1.1. Виртуализация (Windowing)
*   **Двумерная виртуализация**: Используйте библиотеку `@tanstack/react-virtual` или оптимизированные хуки для виртуализации как по вертикали (строки), так и по горизонтали (колонки).
*   **Viewport + Overscan**: Рендерить только элементы, находящиеся в видимой области, плюс небольшой буфер (overscan) из 3–5 строк и 2–3 колонок для плавного скролла.
*   **Фиксированное позиционирование**: Контейнер ячеек должен иметь абсолютное позиционирование с использованием `translate3d(x, y, 0)` или `transform` для аппаратного ускорения отрисовки браузером.

### 1.2. Мемоизация (Strict Memoization)
*   Компоненты ячеек (`Cell`), заголовков колонок (`ColumnHeader`) и строк (`RowHeader`) должны быть обернуты в `React.memo` со строгой функцией сравнения пропсов.
*   Избегайте передачи анонимных функций в пропсы ячеек. Все колбэки (клик, изменение фокуса, изменение текста) должны быть обернуты в `useCallback` на уровне сетки таблицы.

---

## 2. Управление состоянием (State Management)

### 2.1. Zustand-стор
Для хранения состояния таблицы используется оптимизированное локальное хранилище Zustand. Использование React Context для частых обновлений (ввод текста, перемещение курсора) запрещено.

### 2.2. Нормализованная структура данных
Данные хранятся в виде плоского словаря (Hash Map) с доступом $O(1)$:

```typescript
interface CellData {
  value: string;
  formula: string | null;
  format: 'currency' | 'percent' | 'number' | 'text';
  style?: {
    bold?: boolean;
    italic?: boolean;
    underline?: boolean;
    align?: 'left' | 'center' | 'right';
  };
}
```

## 3. Пользовательский интерфейс и UX

### 3.1. Клавиатурная навигация и выделение
*   Навигация через `ArrowKeys`, редактирование через `Enter`, переход через `Tab`.
*   Массовое выделение (drag-select): визуализируется синей рамкой, которая покрывает прямоугольник между началом выделения и текущим положением курсора.

### 3.2. Массовое редактирование (Multi-cell Formatting)
*   Любое применение формата (числа, проценты) или стилей (жирный, курсив, выравнивание) должно применяться **ко всему выделенному диапазону** (`selectedRange`).
*   В сторе действие должно пробегать циклом от `minRow` до `maxRow` и от `minCol` до `maxCol` и обновлять объект ячейки для всех найденных адресов, вызывая один ререндер.

### 3.3. Изменение структуры (Контекстные меню и Ресайзинг)
*   **Ресайзинг**: Хендлы на границах заголовков колонок и строк, позволяющие перетаскиванием изменять ширину/высоту.
*   **Контекстные меню**: Строго по навыку `context-menu` (без коллизий с краями экрана, порталы в `document.body`).
*   **Добавление/Удаление**:
    *   При удалении колонки $C$: Все ключи $D \dots Z$ должны сдвинуться влево (стать $C \dots Y$).
    *   При добавлении колонки $C$: Все ключи $C \dots Z$ должны сдвинуться вправо (стать $D \dots AA$).

### 3.4. Буфер обмена (Clipboard)
*   Копирование выделенного диапазона в `TSV` формат. Вставка TSV начиная от `focusedCell` с парсингом `\n` и `\t`.

## 5. Предотвращение ошибок и важные нюансы (Bug Prevention & Gotchas)

### 5.1. Обработка глобального ввода клавиатуры
*   **Проблема**: При редактировании ячейки ввод текста сбрасывается, перезаписывается или первый символ дублируется.
*   **Решение**: 
    1. Глобальный слушатель `keydown` должен проверять наличие редактируемой ячейки через `const isEditing = !!editingCell`. Если `isEditing === true`, глобальный ввод буквенно-цифровых клавиш должен игнорироваться.
    2. При переходе в режим редактирования по нажатию символьной клавиши (`e.key.length === 1`), обязательно вызывайте `e.preventDefault()`. Это предотвратит повторную печать символа браузером в только что сфокусированный `<input>`.
    3. Игнорируйте события клавиатуры, если активный элемент (`document.activeElement`) является инпутом вне таблицы.

### 5.2. Фокусировка контейнера таблицы
*   **Проблема**: После клика на ячейку клавиатурная навигация не реагирует, пока пользователь не кликнет на рамку.
*   **Решение**: При клике на ячейку (`onMouseDown`) или на заголовки столбцов/строк обязательно вызывайте программный фокус на контейнере таблицы:
    ```typescript
    const container = document.querySelector('.spreadsheet-grid-container') as HTMLDivElement;
    if (container) container.focus();
    ```

### 5.3. Перехват событий в Context Menu
*   **Проблема**: Контекстное меню открывается пустым, без действий для строк/колонок.
*   **Решение**: Компонент `ContextMenuTrigger` делает `e.stopPropagation()` для события `onContextMenu`. Обработчик `onContextMenu`, который определяет индекс кликнутой колонки или строки, должен вешаться на элемент **внутри** `ContextMenuTrigger` (или на дочерние элементы), а не на родительский `div`, иначе событие до него просто не дойдет.

### 5.4. Синхронизация ресайза с виртуализатором
*   **Проблема**: При изменении ширины колонки или высоты строки визуально сетка ломается или ячейки накладываются друг на друга.
*   **Решение**: Сразу после изменения размера в сторе вызывайте метод `.measure()` соответствующего виртуализатора (`colVirtualizer.measure()` или `rowVirtualizer.measure()`), чтобы сбросить закешированные координаты и заставить сетку пересчитать позиции элементов.

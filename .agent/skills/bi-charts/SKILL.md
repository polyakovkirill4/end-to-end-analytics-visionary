# BI, Графики и Аналитические Таблицы

Этот навык устанавливает стандарты для визуализации бизнес-метрик с помощью интерактивных графиков и аналитических таблиц, обеспечивая высокую производительность и безупречный UX как на десктопах, так и на мобильных устройствах.

## 1. Стек и принципы реализации графиков

*   **Минимизация JS-бандла**: Во избежание раздувания бандла и проблем совместимости с React 19, графики разрабатываются на чистом SVG или Canvas с использованием стандартного React API. Избегайте подключения тяжелых внешних библиотек визуализации, если это не согласовано отдельно.
*   **Изоляция расчетов**: Все математические расчеты (масштабирование, координаты осей, углы секторов) должны производиться через `useMemo` для предотвращения лишних перерисовок.
*   **Состояния загрузки (Loading State)**:
    *   Если данные загружаются асинхронно, внутри контейнера графика должен отображаться аккуратный скелетон или лоудер (спиннер/индикатор), центрированный и оформленный в стиле проекта.
    *   Контейнер во время загрузки должен сохранять свои целевые размеры, чтобы избежать скачков верстки (CLS).

## 2. Разновидности графиков
Используйте наиболее подходящий тип графика для конкретных данных:
*   **Линейный график (Line Chart)**: Для отображения трендов во времени (выручка, расходы, прибыль по месяцам/дням). Линии должны быть толщиной `2px`–`2.5px` со скругленными стыками (`strokeLinecap="round" strokeLinejoin="round"`).
*   **Столбчатая диаграмма (Bar Chart)**: Для сравнения категорий или дискретных периодов (продажи по менеджерам, количество новых учеников по месяцам).
*   **Круговая / Пончиковая диаграмма (Pie / Donut Chart)**: Для отображения долей в общем объеме (структура расходов, популярность направлений танго).
*   **Другие типы**: Можно использовать любые другие графики и диаграммы, если они качественнее и понятнее визуализируют специфичные бизнес-данные.

## 3. Дизайн, Отступы и Анимации

*   **Цветовая схема**: Не хардкодьте произвольные цвета. Используйте цвета, сочетающиеся с фирменным цветом в проекте (в соответствии с глобальной дизайн-системой, Tailwind-конфигом или CSS-переменными темы).
*   **Интерактивность (Hover-эффекты)**:
    *   При наведении на точки, столбцы или сектора диаграммы они должны плавно изменять прозрачность, размер или цвет (например, с помощью Tailwind-классов `transition-all duration-200`).
    *   Подсвечивайте текущую активную линию или столбец, приглушая остальные для концентрации внимания.
*   **Отступы (Padding / Margin)**: У блока графиков должны быть нормальные, аккуратные отступы (не слишком большие). В мобильной версии отступы контейнера необходимо сделать минимальными, чтобы сэкономить пространство для данных.
*   **Плавное обновление данных (Transitions)**: При изменении или обновлении данных график не должен полностью перерисовываться (моргать или исчезать). Отрисованный график должен плавно изменять свои элементы (анимация перестроения линий/столбцов) к новым значениям.

## 4. UX Всплывающих подсказок (Tooltips)

Всплывающая подсказка (Tooltip) является главным источником детализации:
*   **Позиционирование по Z-оси**: Тултип должен иметь высокий приоритет отображения (высокий `z-index`), чтобы гарантированно перекрывать любые соседние блоки, оси и элементы управления.
*   **Предотвращение выхода за границы**: Реализуйте алгоритм динамического расчета координат. Тултип должен сдвигаться влево/вправо/вверх/вниз так, чтобы он никогда не выходил за границы экрана или контейнера графика (особенно на смартфонах).
*   **Форматирование данных**: Значения внутри тултипа должны строго соответствовать правилам из файла `formatting-data.md` (разделители тысяч, знак рубля после пробела, проценты без пробела и т.д.).
*   **Округление**: Для нецелых числовых значений по умолчанию округляйте данные до десятых, если иное не продиктовано требованиями бизнес-логики.
*   **Сортировка в легенде**: Если на графике отображается несколько показателей одновременно, сортируйте строки в тултипе по убыванию значений в текущей точке, чтобы пользователь сразу видел лидирующие категории.
*   **Триггеры вызова**: На десктопе тултип вызывается при наведении мышки (hover), а на мобильных устройствах — исключительно по клику (touch/tap) на график.
*   **Комбинированные графики (Shared Tooltip)**: Если на графике выводится несколько метрик одновременно, при вызове тултипа он должен показывать значения **всех добавленных графиков/метрик** для данной точки на оси X.

## 5. Мобильная адаптация графиков

Графики должны оставаться читаемыми на мобильных устройствах:
1.  **Динамический Resize**: Используйте `ResizeObserver` для получения реальных размеров родительского контейнера и пропорционального пересчета координат точек графика.
2.  **Оптимизация подписей осей**:
    *   На мобильных экранах уменьшайте размер шрифта подписей осей и легенды (например, до `text-xs` или `10px`).
    *   Уменьшайте внешние и внутренние отступы контейнера графика.
    *   Обязательно прореживайте подписи по оси X (например, отображайте каждый 2-й, 3-й или только первый и последний элементы ряда), чтобы текст не накладывался друг на друга.
3.  **Тач-события**: Поддерживайте корректную обработку Touch-событий (`onTouchStart`, `onTouchMove`, `onTouchEnd`) для отображения тултипов на мобильных устройствах.

## 6. Аналитические Таблицы и Таблица Итогов

*   **Сводная таблица под графиком (Таблица Итогов)**: Под блоком любого графика всегда располагайте "Таблицу Итогов" (Total Table), агрегирующую данные, выводимые на графике (сумма, среднее и т.д.). Это позволяет клиенту быстро считывать итоговые результаты.
*   **Оформление шапки**: Шапка таблицы должна быть четко выделена визуально (более темный или контрастный фон, полужирный шрифт заголовков, аккуратные нижние границы).
*   **Горизонтальная прокрутка**:
    *   Для таблиц с большим количеством колонок обязательно настраивайте контейнер с горизонтальной прокруткой (`overflow-x-auto`).
    *   Прокрутка должна быть плавной и не должна ломать верстку окружающих блоков.
*   **Закрепление первой колонки**:
    *   Первая колонка (например, ФИО, название филиала или показатель) должна оставаться закрепленной (`sticky left-0 bg-white z-10`), чтобы при горизонтальном скролле пользователь не терял контекст.
    *   Добавляйте к закрепленной колонке легкую тень (shadow) справа при прокрутке, чтобы визуально отделить ее от прокручиваемых данных.
*   **Ховеры (Hover-эффекты)**:
    *   Подсвечивайте строку при наведении (`hover:bg-gray-50` или аналогичный класс).
    *   При необходимости настраивайте подсветку активной колонки или отдельной ячейки.
    *   **Внимание**: Убедитесь, что при горизонтальной прокрутке hover-эффект строки работает корректно и синхронно на закрепленных (`sticky`) и прокручиваемых ячейках. У них должен быть одинаковый фон при наведении.
*   **Сворачивание и группировка строк**:
    *   При древовидной структуре или группировке данных (например, категории расходов и подкатегории) реализуйте сворачивающиеся/разворачивающиеся группы (аккордеоны).
    *   Добавляйте понятные индикаторы состояния (стрелочки/иконки `chevron-down` / `chevron-right`), которые плавно вращаются при изменении состояния.
*   **Адаптация шрифтов**: На мобильных устройствах уменьшайте размер шрифта в таблицах (например, до `text-xs`) и минимизируйте внутренние отступы ячеек (`px-2 py-1.5` вместо `px-4 py-3`), чтобы на экране помещалось больше полезной информации.

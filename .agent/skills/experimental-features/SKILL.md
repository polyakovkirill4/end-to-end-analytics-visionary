# Создание экспериментальных функций (Experimental Features & Sandbox)

Этот навык регламентирует стандарты проектирования, размещения кода и контроля доступа при создании экспериментального функционала (MVP/Proof of Concept) по запросу пользователя.

---

## 1. Архитектурный подход: Feature Toggles и Co-location

Для тестирования нового функционала без риска для стабильности системы и реальных клиентов используется паттерн **Feature Toggles (Feature Flags)** в связке с архитектурным подходом **Co-location** (совместное размещение ресурсов).

> [!IMPORTANT]
> **Запрещено** создавать глобальную общую папку `labs` и сваливать туда все экспериментальные компоненты, хуки и утилиты. Это создает хаос в импортах и усложняет будущий релиз или удаление фичи.

* **Co-location**: Весь код экспериментальной функции должен находиться внутри одной изолированной папки в директории `src/features/`.
* **Быстрое удаление**: Если эксперимент признан неудачным, разработчик может удалить одну папку в `src/features/` и ссылки на неё, оставив кодовую базу абсолютно чистой.
* **Переход в релиз**: Если эксперимент удался, файлы не нужно перемещать — фича просто включается (активируется) для всех пользователей через Feature Flag.

---

## 2. Структура папок: Группировка по фичам (Feature-based)

Каждая экспериментальная разработка получает собственную изолированную директорию внутри `src/features/`. Внутри этой директории размещается только то, что относится к данной конкретной фиче.

```plaintext
src/
 ├── app/                      # Роутинг Next.js
 ├── components/               # Глобальные UI компоненты общего назначения (кнопки, инпуты)
 ├── lib/                      # Глобальные утилиты и клиенты (supabase client)
 └── features/                 # Бизнес-модули (включая экспериментальные)
      ├── advanced-forecasting/  # Папка экспериментальной фичи
      │    ├── components/       # Локальные компоненты только для этой фичи
      │    ├── hooks/            # Локальные хуки (например, useForecastData)
      │    ├── types.ts          # Локальная типизация моделей
      │    └── index.ts          # Публичный API фичи (экспорты наружу)
      └── ...
```

## 3. Роутинг и Страницы (Next.js App Router)

Внедрение экспериментального функционала в интерфейс разделяется на два основных сценария в зависимости от масштаба задачи:

### Сценарий А: Полностью новая страница (Новый раздел)
Если тестируется целый новый раздел (например, новый генератор отчетов), страница создается внутри выделенной группы роутинга Next.js (Route Groups), которая физически отделена от основного клиентского интерфейса.
* **Путь по умолчанию**: Использовать группу роутов `(labs)` для создания скрытой зоны `/labs/...`.
* **Запрет на `/test`**: Запрещается использовать слово `test` в адресах URL (пути `/labs/ai-reports` приветствуются, `/test-reports` — запрещены).

```plaintext
src/app/
 ├── (main)/             # Основной интерфейс клиентов
 └── (labs)/             # Скрытая экспериментальная зона
      └── labs/
           └── ai-reports/
                └── page.tsx # Страница доступна только с проверкой прав доступа
```

* **Обязательный запрос у пользователя**: Перед созданием страницы агент **обязан спросить пользователя**, в каком именно разделе/URL разместить новый функционал, поскольку он может потребоваться в специфическом месте проекта.

### Сценарий Б: Экспериментальный блок на существующей странице
Если добавляется новый график или интерактивный блок на уже существующий рабочий дашборд, оригинальная страница не дублируется. Блок встраивается непосредственно в рабочий код страницы/компонента, но обязательно оборачивается в Feature Flag.

```tsx
{/* Существующий интерфейс дашборда */}
<DashboardHeader />
<MetricsGrid />

{/* Экспериментальный блок, скрытый за флагом */}
{hasFeatureFlag('advanced-forecasting') && (
  <Suspense fallback={<Loader />}>
    <AdvancedForecastingChart />
  </Suspense>
)}
```

## 4. Концепция изолированной быстрой разработки (All-in-One для MVP)

Для сохранения высокой скорости на этапе прототипирования:
1. Первоначальный MVP-код страницы или фичи пишется по принципу **All-in-One** (все вспомогательные функции, локальные типы данных и UI-элементы описываются прямо в файле страницы или в едином файле фичи в `src/features/[feature-name]`).
2. Это позволяет быстро проверить концепт, не плодя десятки пустых файлов на ранних этапах.
3. По мере стабилизации требований код внутри папки фичи разбивается на подпапки (`components/`, `hooks/`), подготавливаясь к релизу.

---

## 5. Ограничение доступа и Feature Flags (RBAC)

Поскольку экспериментальный функционал нестабилен, он должен быть скрыт от обычных пользователей в продакшене.

* **Интеграция с RBAC**: Доступ должен управляться через систему ролей и разрешений (permissions) проекта. Запрещается хардкодить роли (`role === 'admin'`).
* **Проверка прав**: Страницы в `(labs)` и компоненты под флагами должны проверять разрешения текущего пользователя в системе RBAC (например, наличие разрешения `access_labs_features` или индивидуального флага фичи).

### Пример защиты страницы в группе `(labs)`:

```tsx
'use client';

import React from 'react';
import { useRouter } from 'next/navigation';
import { useRBAC } from '@/hooks/useRBAC'; // Хук системы контроля доступа
import { Loader2, ShieldAlert } from 'lucide-react';

export default function ExperimentalPlaygroundPage() {
  // Проверяем доступ к экспериментальной зоне
  const { hasPermission, isLoading } = useRBAC('access_labs_features');
  const router = useRouter();

  if (isLoading) {
    return (
      <div className="h-screen w-screen flex items-center justify-center bg-slate-50">
        <Loader2 className="w-8 h-8 text-indigo-600 animate-spin" />
      </div>
    );
  }

  if (!hasPermission) {
    return (
      <div className="h-screen w-screen flex flex-col items-center justify-center bg-slate-50 p-6 text-center">
        <div className="w-16 h-16 bg-rose-50 text-rose-600 rounded-2xl flex items-center justify-center mb-4">
          <ShieldAlert className="w-8 h-8" />
        </div>
        <h1 className="text-xl font-bold text-slate-900 mb-2">Доступ ограничен</h1>
        <p className="text-xs text-slate-500 max-w-sm mb-6">
          У вас нет прав для доступа к экспериментальным функциям. Настройте разрешения в панели RBAC.
        </p>
        <button
          onClick={() => router.push('/')}
          className="px-5 py-2.5 bg-indigo-600 text-white rounded-xl text-xs font-bold shadow-md hover:bg-indigo-700 transition-all active:scale-95"
        >
          Вернуться на главную
        </button>
      </div>
    );
  }

  return (
    <div className="p-8 max-w-7xl mx-auto">
      <h1 className="text-2xl font-bold text-slate-900 mb-6">Лаборатория: Прогнозирование данных</h1>
      {/* MVP-код фичи */}
    </div>
  );
}
```

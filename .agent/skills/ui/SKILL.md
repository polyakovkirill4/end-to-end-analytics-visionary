# Навык: Premium UI & Forms Expert (Стандарты UI/UX)

Этот навык определяет строгие стандарты для пользовательских интерфейсов, форм, валидации и визуального дизайна в платформе SaaS Analytics. Мы создаем премиальный, современный и отзывчивый интерфейс.

## 1. Базовые принципы дизайна (Premium Aesthetics)

*   **Цвета и типографика**:
    *   Используй современные шрифты (Inter, Roboto) с правильной иерархией размеров и насыщенности (`font-medium`, `font-semibold`).
    *   Избегай базовых цветов (простой красный или синий). Используй гармоничные палитры Tailwind (например, `indigo-600` для primary, `emerald-500` для успеха, `rose-500` для ошибок).
    *   Используй цвет `slate` или `gray` для текстов: `text-slate-900` для заголовков, `text-slate-500` для второстепенного текста.
*   **Эффекты и Глубина**:
    *   Используй мягкие тени (`shadow-sm`, `shadow-md`) для карточек и модальных окон.
    *   Для "липких" (sticky) шапок или панелей используй эффект Glassmorphism: `bg-white/80 backdrop-blur-md`.
*   **Микроанимации**:
    *   Все интерактивные элементы (кнопки, ссылки, карточки) должны иметь `transition-all duration-200`.
    *   Добавляй эффекты при наведении (`hover:bg-slate-50`) и нажатии (`active:scale-[0.98]`).

## 2. Выбор компонентов (ОБЯЗАТЕЛЬНО)

*   **Select / Dropdown**:
    *   **НИКОГДА** не используй стандартный HTML `<select>`. Он ломает UX на мобильных устройствах.
    *   **ВСЕГДА** используй кастомный `components/ui/SearchableSelect` (или аналогичный).
*   **Multi-Select**:
    *   Используй `components/ui/MultiSelect`. Не строй списки чекбоксов вручную, если это не обосновано дизайном.
*   **Поиск (Search)**:
    *   Используй `components/ui/SearchInput`.
    *   **Пустое состояние (Empty State)**: Если поиск ничего не нашел, обязательно показывай блок "Ничего не найдено" с иконкой.

## 3. Формы и поля ввода (Inputs Behavior)

### Числовые поля (Number Inputs)
*   **Ведущие нули**: При фокусе на числовом поле, где по умолчанию стоит `0`:
    *   Пользователь НЕ должен вручную стирать `0`.
    *   *Реализация*: Используй `placeholder="0"`, храни значение как пустую строку `""` или `null`, если значение равно `0`. Либо используй `onFocus={(e) => e.target.select()}`, чтобы сразу выделить текст.

### Сложные поля
*   **Тултипы (Tooltips)**: Для сложных или непонятных полей обязательно добавляй иконку `(?)` с тултипом, объясняющим суть поля.

### Состояния загрузки (Loading States)
*   При отправке формы:
    *   Кнопка "Сохранить" **ДОЛЖНА** показывать спиннер (`<Loader2 className="animate-spin" />`).
    *   Кнопка должна быть `disabled`, чтобы предотвратить двойную отправку.

## 4. Кнопки и интерактивные элементы

*   **Disabled состояния**: Если кнопка неактивна (например, нет прав или форма не заполнена), рассмотри возможность добавить Tooltip, объясняющий *почему* она недоступна.
*   **Иконки**: Используй иконки (например, из `lucide-react`) для кнопок действий, чтобы улучшить визуальное считывание.

## 5. Отображение данных и состояний

*   **Пустые состояния (Empty States)**:
    *   Никогда не показывай пустую таблицу или пустой экран.
    *   Обязательно выведи красивый компонент `EmptyState` с иллюстрацией/иконкой, текстом (например: "У вас пока нет проектов") и кнопкой призыва к действию (CTA - "Создать проект").
*   **Загрузка (Skeletons)**:
    *   При первичной загрузке данных на странице используй `Skeleton` (пульсирующие серые блоки) вместо крутящегося спиннера на весь экран. Это предотвращает "прыжки" интерфейса (Layout Shift).

## 6. Валидация и обработка ошибок

*   **Обязательные поля**:
    *   Отмечай визуально (например, красной звездочкой `*`).
    *   **Текст ошибки**: Если поле не заполнено, выводи четкий текст ошибки под полем: "Обязательное поле для заполнения".
*   **Уведомления (Toasts)**:
    *   При успешном сохранении показывай Success Toast ("Успешно сохранено").
    *   При ошибке с сервера показывай Error Toast с понятным текстом (обрабатывай ошибки правильно, не выводи сырой `[Object object]`).

## 7. Модальные окна и Drawer

*   **Фокус**: При открытии модального окна фокус должен автоматически ставиться на первое поле ввода.
*   **Закрытие**: Окно должно закрываться по клику на фон (Overlay) и по нажатию клавиши `Esc`.
*   **Адаптивность**: На мобильных экранах (`< 768px`) модальные окна желательно превращать в Bottom Sheet (шторку снизу) или открывать на весь экран для удобства.

## 8. Пример кода формы (React Hook Form)

```tsx
import { useForm } from 'react-hook-form';
import { SearchableSelect } from '@/components/ui/SearchableSelect';
import { Button } from '@/components/ui/Button';
import { Loader2, Info } from 'lucide-react';

export function ExampleForm() {
  const { register, handleSubmit, formState: { errors, isSubmitting } } = useForm();

  const onSubmit = async (data) => {
    // API call...
  };

  return (
    <form onSubmit={handleSubmit(onSubmit)} className="space-y-4">
      {/* Number Input с правильным UX */}
      <div className="flex flex-col gap-1.5">
        <label className="flex items-center gap-2 text-sm font-medium text-slate-700">
          Стоимость
          <Tooltip content="Укажите стоимость в рублях">
            <Info className="w-4 h-4 text-slate-400" />
          </Tooltip>
        </label>
        <input 
          type="number" 
          placeholder="0"
          {...register('cost', { required: "Обязательное поле для заполнения", valueAsNumber: true })}
          className="input-class transition-all duration-200 focus:ring-2 focus:ring-indigo-500"
          onFocus={(e) => e.target.select()}
        />
        {errors.cost && (
          <span className="text-xs text-rose-500">{errors.cost.message as string}</span>
        )}
      </div>

      {/* Сохранение с лоадером и микроанимацией */}
      <Button 
        type="submit" 
        disabled={isSubmitting} 
        className="w-full bg-indigo-600 hover:bg-indigo-700 active:scale-[0.98] transition-all"
      >
        {isSubmitting ? <Loader2 className="w-4 h-4 mr-2 animate-spin" /> : 'Сохранить'}
      </Button>
    </form>
  );
}
```

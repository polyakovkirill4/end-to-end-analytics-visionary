# Производительность, масштабируемость и оптимизация

Этот документ содержит рекомендации по обеспечению максимальной производительности, масштабируемости и скорости отклика интерфейсов платформы Visionary.

## 1. Лимиты времени выполнения (Latency)
- **Лимит 200мс**: Любая интерактивная операция (клики по кнопкам, переключение вкладок, расчеты на клиенте) должна отрабатывать визуально мгновенно.
- Если вычисление или запрос к БД может занять более **200мс**, необходимо:
  1. Реализовать асинхронное выполнение.
  2. Вывести индикатор загрузки (skeleton loader, spinner) с плавным переходом.
  3. Для длительных фоновых процессов использовать очереди задач или веб-воркеры.

## 2. Оптимизация запросов и кэширование (TanStack Query)
- **TanStack Query (React Query)** является основным инструментом для работы с сервером и базой данных на клиенте.
- Запрещено использовать цепочки `useEffect` для запросов данных при монтировании компонента.
- Настройка кэширования:
  - Устанавливай адекватное время жизни кэша (`staleTime` и `gcTime`) для статических или редко меняющихся данных (например, справочники, профиль пользователя, список проектов).
  - Используй инвалидацию кэша (`queryClient.invalidateQueries`) после мутаций (`useMutation`), чтобы поддерживать актуальность данных.
- **Оптимистичные обновления (Optimistic Updates)**: Применяй для частых действий (лайки, добавление записей, смена статусов), чтобы пользователь видел изменения в интерфейсе мгновенно, до завершения сетевого запроса.

## 3. Управление состоянием (Zustand & React State)
- **Zustand** используется исключительно для глобального состояния, разделяемого между независимыми экранами и сайдбарами (например, активная организация, состояние сворачивания сайдбара, тема оформления).
- **Локальный стейт (`useState`)** должен оставаться внутри компонентов, если он не нужен в других ветвях UI-дерева.
- Для предотвращения лишних ререндеров в Zustand используй селекторы:
  ```typescript
  const sidebarOpen = useUIStore((state) => state.sidebarOpen); // Правильно
  const { sidebarOpen } = useUIStore(); // Нежелательно (вызовет ререндер при любом изменении стора)
  ```

## 4. Оптимизация рендеринга и бандла (React 19 & Next.js 15)
- **Ленивая загрузка (Lazy Loading)**: Тяжелые компоненты (например, конструкторы дашбордов, интерактивные таблицы-спредшиты, библиотеки графиков) импортируй динамически через `next/dynamic`.
- **Оптимизация изображений**: Всегда используй компонент `Image` из `next/image` с указанием размеров или разметки `fill`, чтобы избежать сдвигов верстки (Layout Shift) и оптимизировать размеры файлов.
- **Минимизация CSS**: Не дублируй inline-стили Tailwind. Если группа классов повторяется более 3 раз, вынеси её в переиспользуемый UI-компонент.

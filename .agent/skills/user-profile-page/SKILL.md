# Разработка базовой страницы пользователя (User Profile Page)

Данное руководство описывает стандарты верстки, структуры полей, интерактивной логики и безопасности для страницы настроек профиля пользователя (Личного кабинета) в Next.js и React приложениях.

---

## 1. Расположение файлов и структура

В типичном проекте интерфейс профиля разделяется на следующие сущности:
*   **Страница настроек (Page):** `src/app/(main)/profile/page.tsx` (или `src/app/(main)/settings/page.tsx`) — основной контейнер с вкладками.
*   **Компоненты разделов (Tabs):** 
    *   `src/components/profile/PersonalDataTab.tsx` — вкладка личных данных и аватара.
    *   `src/components/profile/SecurityTab.tsx` — формы смены email и пароля.
    *   `src/components/profile/NotificationsTab.tsx` — управление уведомлениями и рассылками.
*   **Компоненты UI:** `src/components/ui/` (Input, Select, Switch, Toast, Avatar).

---

## 2. Поля профиля и валидация

Интерфейс профиля должен четко разделять редактируемые данные от служебных, которые доступны только для чтения.

### Редактируемые поля (Editable Fields)
1.  **Имя** (First Name): Отдельное текстовое поле. Обязательное. Валидация: минимум 2 символа.
2.  **Фамилия** (Last Name): Отдельное текстовое поле. Обязательное. Валидация: минимум 2 символа.
3.  **Отчество** (Middle Name / Patronymic): Отдельное текстовое поле. Опциональное (зависит от настроек проекта).
4.  **Телефон** (Phone): Поле ввода телефона. Валидация: соответствие маске региона (например, РФ: `+7 (999) 999-99-99`).
5.  **Имя пользователя** (Username): Текстовое поле. Опциональное (зависит от проекта). Валидация: только латиница, цифры, точки и нижние подчеркивания, уникальность на сервере.
6.  **Пол** (Gender): Выпадающий список (Select) со значениями: *Мужской*, *Женский*, *Другой*, *Не указан*.

### Только для чтения / Служебные поля (Read-Only Fields)
Эти поля отображаются информационно, редактирование напрямую запрещено (или доступно только администраторам):
1.  **Роль в компании / Должность:** Текстовый бейдж (например, «Администратор», «Аналитик», «Менеджер»).
2.  **Права доступа на платформе:** Список доступных прав или уровень доступа в системе безопасности (RBAC).
3.  **Дата регистрации:** Дата создания аккаунта. Форматируется по правилу проекта (например, через `formatDate`).
4.  **ID профиля (UUID):** Уникальный идентификатор записи в БД.
    *   *Важно:* Скрывается по умолчанию. Должен показываться только по запросу/клику на кнопку «Показать ID» или быть доступен для быстрого копирования в один клик.

## 3. Загрузка фотографии профиля (Avatar Drag & Drop)

Зона загрузки аватара должна поддерживать два сценария: перетаскивание файла (Drag & Drop) и клик для выбора файла.

### Логика работы
1.  **Состояние Drag-Over:** При перетаскивании файла над зоной аватара рамка контейнера должна менять цвет на акцентный (`border-primary` или `border-dashed border-[var(--color-primary)]`), показывая готовность принять файл.
2.  **Валидация файлов на клиенте:**
    *   *Форматы:* Разрешены только изображения: `.png, .jpg, .jpeg, .webp` (MIME-типы `image/*`).
    *   *Размер:* Ограничение максимального размера (например, до 5 МБ). При нарушении ограничений выводить Toast об ошибке.
3.  **Превью (Preview):** При успешном выборе или сбросе файла сразу отображается клиентское превью (через `URL.createObjectURL(file)`), а в фоне запускается процесс отправки на сервер.
4.  **Индикация загрузки:** Во время отправки изображения на сервер поверх превью аватара должен накладываться полупрозрачный слой с лоадером (Spinner) и текстом «Загрузка...».

### Пример базовой обработки событий Drag & Drop в React:
```tsx
const [isDragging, setIsDragging] = useState(false);

const handleDragOver = (e: React.DragEvent) => {
  e.preventDefault();
  setIsDragging(true);
};

const handleDragLeave = () => {
  setIsDragging(false);
};

const handleDrop = async (e: React.DragEvent) => {
  e.preventDefault();
  setIsDragging(false);
  const file = e.dataTransfer.files?.[0];
  if (file && file.type.startsWith('image/')) {
    // Валидация размера и вызов API отправки
    await uploadAvatar(file);
  } else {
    toast.error('Допускаются только файлы изображений');
  }
};
```

## 4. Раздел Безопасности (Изменение Email и Пароля)

Формы изменения учетных данных должны быть защищены и изолированы в отдельные логические карточки или блоки.

### Изменение Email
*   Отображение текущего адреса в формате: `Текущий адрес: ivan.ivanov@example.ru` (только для чтения).
*   Поле ввода **Новый Email адрес**.
*   Кнопка отправки «Обновить Email» / «Сохранить».
*   *Логика:* После успешной отправки формы пользователю на новый email (или оба адреса) отправляется письмо-подтверждение. В интерфейсе выводится сообщение: *«На ваш новый адрес отправлено письмо для подтверждения смены Email»*.

### Изменение пароля
Форма должна содержать три поля:
1.  **Текущий пароль** (Current Password).
2.  **Новый пароль** (New Password): Валидация длины (минимум 8 символов) и сложности (наличие цифр, спецсимволов).
3.  **Подтвердить новый пароль** (Confirm Password): Валидация совпадения с новым паролем.
*   *Текст-подсказка:* «Используйте надежный пароль для защиты вашего аккаунта».
*   *Интерактивность:* Каждое поле должно иметь кнопку-глазок (`Eye` / `EyeOff`) для переключения видимости пароля.

## 5. Раздел Настройки Уведомлений и Рассылок

Настройки уведомлений реализуются в виде группы интерактивных переключателей (Switches). Изменение состояния должно немедленно отправлять запрос на сервер (или сохраняться по кнопке «Сохранить» в конце раздела).

Раздел делится на три блока настроек:
1.  **Блок Push-уведомлений:** Оповещения в реальном времени внутри веб-приложения / браузера (системные события, срочные предупреждения).
2.  **Блок Email-уведомлений:** Получение отчетов, сводок за день/неделю, писем об активности на почту.
3.  **Блок рассылок по типам (Mailing Subscriptions):**
    *   *Маркетинговые рассылки* (новости, обновления продукта, специальные предложения).
    *   *Сервисные/Системные рассылки* (уведомления об изменении тарифов, технические работы, критические изменения в безопасности).
    *   *Обновления платформы* (новости о новых функциях, улучшениях, релизах).
    *   *Обучающие материалы* (руководства, вебинары, дайджесты лучших практик).
    *   *Другие категории* (подумай какие еще могут быть полезные для проекта).

## 6. Визуальный стиль, обратная связь и мобильный UX

*   **Успешное обновление (Toasts):** Любое успешное действие по обновлению профиля (сохранение личных данных, смена пароля, переключение настроек уведомлений) должно сопровождаться всплывающим Toast-сообщением с текстом успешного статуса (например, *«Личные данные успешно сохранены»*, *«Настройки уведомлений обновлены»*).
*   **Интерактивные состояния:**
    *   Кнопки сохранения во время выполнения сетевого запроса должны переходить в состояние `disabled` и показывать индикатор загрузки (Spinner).
    *   Во время редактирования полей при вводе невалидных данных (например, слишком короткий пароль) валидация должна подсвечивать границу инпута красным цветом и выводить текст ошибки мелким шрифтом снизу.
*   **Мобильная адаптивность:**
    *   **Боковое меню вкладок:** На десктопе отображается вертикальным списком слева. На мобильных устройствах (ширина `< 1024px`) перестраивается в горизонтальный скролл-бар без видимой полосы прокрутки (`overflow-x-auto hide-scrollbar flex-row`).
    *   **Сетка полей:** Формы личных данных на десктопе выводятся в две колонки (`grid-cols-2`), на планшетах и мобильных телефонах сжимаются в одну колонку (`grid-cols-1`).
    *   **Кнопки действий:** На мобильных устройствах кнопки «Отмена» и «Сохранить» должны занимать 100% ширины экрана и выстраиваться в колонку.

## 7. Чек-лист проверки реализации для ИИ-агента

Перед тем как завершить задачу по странице профиля пользователя, убедись, что:
1. [ ] Поля «Имя» и «Фамилия» разделены на два отдельных поля ввода.
2. [ ] Поле «Отчество» и «Username» добавлены с учетом требований конкретного проекта (если требуются).
3. [ ] Роль, Права доступа, Дата регистрации и ID профиля закрыты для ручного редактирования (`readOnly` или `disabled`).
4. [ ] ID профиля скрыт под кнопку «Показать» или реализовано копирование в один клик.
5. [ ] Зона загрузки аватара поддерживает перетаскивание файлов (Drag & Drop) с визуальной индикацией `isDragging` и валидацией размера/формата.
6. [ ] Форма смены пароля проверяет совпадение «Нового пароля» и «Подтверждения нового пароля», а поля поддерживают скрытие/показ символов.
7. [ ] Настройки уведомлений содержат раздельные переключатели для push, email и маркетинговых/сервисных рассылок.
8. [ ] При любом успешном действии отправляется Toast-сообщение об успехе.
9. [ ] Вкладки навигации на мобильном экране адаптированы под горизонтальный скролл, а инпуты перестраиваются в одну колонку.

# Витрина UI-компонентов (Component Showcase)

Этот навык устанавливает правила использования, наполнения и поддержки страницы-витрины (Showcase / Test Page) для изолированного тестирования и документирования пользовательского интерфейса. 

## 1. Главные правила для ИИ-разработчика

Когда вы создаете, изменяете или переносите UI-компоненты в проекте, вы обязаны следовать следующим инструкциям:

1. **Запрос на добавление на витрину**:
   При разработке любого нового UI-компонента или значительной модификации существующего, вы **должны спросить пользователя**, нужно ли добавить этот компонент (или его новые состояния) на тестовую страницу-витрину.
   *Пример вопроса:* *"Я разработал новый компонент `MyInput`. Добавить ли его демонстрационную версию на страницу тестирования UI-компонентов?"*

2. **Обеспечение полной интерактивности**:
   Все компоненты, размещенные на странице-витрине, должны быть полностью работоспособными. Запрещается отображать чисто «статический» или некликабельный макет интерактивного элемента.
   * Все обработчики событий (`onClick`, `onChange`, `onSubmit` и т.д.) должны работать.
   * Динамические состояния (открытие модальных окон, изменение значений полей, переключение табов, анимации загрузки) должны полноценно функционировать с использованием изолированных локальных состояний (`useState`).
   * Если компонент выполняет асинхронную операцию, на странице-витрине должна быть реализована имитация этой операции (например, сетевая задержка с лоудером) для демонстрации всех состояний интерфейса.

3. **Соблюдение изоляции**:
   Компоненты на витрине должны быть изолированы друг от друга. Изменение состояния или ввод данных в одном демонстрационном блоке не должны неявно влиять на работу соседних блоков.

---

## 2. Назначение и принципы страницы-витрины

Страница-витрина является центральным хабом для команды разработчиков и служит для:
* **Изолированного тестирования**: проверка работы компонента в отрыве от сложной бизнес-логики и внешних API данных.
* **Проверки адаптивности**: визуальное тестирование правильного отображения элементов на экранах разной ширины (мобильные устройства, планшеты, десктопы) и при переключении цветовых тем (если применимо).
* **Примеров использования**: витрина служит живой документацией — кодовая база этой страницы показывает другим разработчикам правильные паттерны вызова компонента и передачи в него параметров (Props).

---

## 3. Правила наполнения страницы при согласии пользователя

При получении согласия от пользователя на добавление компонента на витрину:
1. Разместите его в соответствующей логической группе на странице.
2. **Демонстрируйте все состояния компонентов**: Если у компонента предусмотрены различные визуальные или логические состояния, их все необходимо наглядно показать на витрине. Например:
   * Для интерактивных элементов (кнопок, инпутов и т.д.): состояние по умолчанию, фокус, наведение (hover), заблокированное (disabled), а также состояние загрузки (loading) или отправки.
   * Для форм и карточек: отображение процесса отправки данных, состояния с ошибками валидации, а также состояния успешного выполнения операции.
3. Прокиньте тестовые mock-данные для демонстрации всех возможных визуальных конфигураций.
4. Добавьте текстовые пояснения о том, какие параметры демонстрируются.
5. Проверьте, что добавление нового элемента на страницу-витрину не ломает верстку соседних блоков и сохраняет адаптивность страницы.

# Разработка страниц ошибок 404 и 500 (Error Pages)

Данное руководство описывает стандарты верстки, структуры и логики для страниц ошибок 404 (Страница не найдена) и 500 (Внутренняя ошибка сервера / критический сбой клиента) в рамках Next.js и React приложений.

---

## 1. Расположение файлов и структура

В зависимости от используемого фреймворка, файлы страниц ошибок должны располагаться по следующим путям:

### Next.js (App Router)
*   **404 (Not Found):** `src/app/not-found.tsx` — рендерится автоматически при вызове функции `notFound()` или переходе на несуществующий роут.
*   **500 / Критическая ошибка приложения:** `src/app/error.tsx` — клиентский компонент с обработчиком ошибок (Error Boundary) для конкретного сегмента роута.
*   **Глобальный сбой (включая Root Layout):** `src/app/global-error.tsx` — используется для отлова ошибок в самом корневом макете приложения.

### Next.js (Pages Router)
*   **404:** `src/pages/404.tsx` (или `.js` / `.jsx`).
*   **500 / Системные ошибки:** `src/pages/500.tsx` (или `src/pages/_error.tsx` для кастомизации обоих кодов).

### React (Vite / CRA с React Router v6)
*   **404:** Маршрут-заглушка в конфигурации роутера:
    ```tsx
    { path: "*", element: <NotFoundPage /> }
    ```
*   **500:** Свойство `errorElement` в роутере или глобальный `ErrorBoundary`-компонент:
    ```tsx
    { path: "/", element: <RootLayout />, errorElement: <GlobalErrorPage /> }
    ```

## 2. Сохранение макета (Layout & Sidebars)

Страницы ошибок **не должны ломать пользовательский интерфейс** и заставлять пользователя чувствовать себя потерянным. 

*   **Принцип интеграции:** Ошибка должна рендериться *внутри* текущего контекста и макета приложения (внутри сайдбара, шапки, футера и боковых панелей), если это возможно. Пользователь должен иметь возможность кликнуть на пункты меню в сайдбаре или перейти в другой раздел.
*   **Реализация в Next.js (App Router):** 
    В `not-found.tsx` и `error.tsx` импортируйте и оборачивайте контент в основной лейаут (например, `DashboardLayout` или `MainLayout`), если эти файлы находятся на верхнем уровне приложения.
    ```tsx
    import DashboardLayout from '@/app/(main)/layout';

    export default function NotFound() {
      return (
        <DashboardLayout>
          {/* Контент страницы ошибки */}
        </DashboardLayout>
      );
    }
    ```
*   **Исключение:** Если страница ошибки рендерится для неавторизованного пользователя (в роутах `/auth/*`), макет личного кабинета использовать нельзя. В таком случае должна использоваться общая чистая подложка или макет авторизации.

## 3. Кнопки управления и логика

Каждая страница ошибки обязана иметь четкие призывы к действию (CTA) для выхода из тупика.

### Страница 404 (Not Found)
1.  **Кнопка «Назад»:** Возвращает пользователя на предыдущую страницу в истории браузера.
    *   *Реализация:* Вызов `router.back()` (Next.js) или `history.back()` / `navigate(-1)` (React).
2.  **Кнопка «На главную»:** Ведет на главный дашборд или домашнюю страницу.
    *   *Реализация:* Ссылка на `/` или `/dashboard`.
3.  **Ссылка «Поддержка»:** Дает возможность быстро связаться с саппортом.
    *   *Реализация:* Ссылка на `/support` или вызов виджета чата поддержки.

### Страница 500 / Ошибка сервера / Сбой (Error)
1.  **Кнопка «Обновить страницу» (Повторить попытку):** Сбрасывает состояние ошибки и пытается перерендерить компонент.
    *   *Реализация:* В Next.js `error.tsx` принимает проп `reset: () => void`. Кнопка должна вызывать эту функцию.
2.  **Кнопка «На главную»:** Должна присутствовать на случай, если повторный рендеринг не помог.
3.  **Ссылка «Поддержка»:** Для сообщения о критическом баге.
4.  **Логирование:** Страница сбоя обязана выполнять логирование ошибки во внешние системы мониторинга (Sentry, Logsnag) или консоль в блоке `useEffect`.
    ```tsx
    useEffect(() => {
      console.error('Unhandled application error:', error);
      // Отправка в Sentry/логировщик...
    }, [error]);
    ```

## 4. Динамическая стилизация под любой бренд

Не пишите жестко закодированные (hardcoded) HEX/RGB цвета для кнопок, фонов и акцентов бренда. Компонент должен автоматически перестраиваться под тему текущего проекта.

*   **Использование CSS-переменных проекта:** Применяйте переменные темы Tailwind или стандартные CSS-переменные:
    *   Фон кнопок: `bg-primary` или `bg-[var(--color-primary)]` (вместо жесткого `bg-indigo-600`).
    *   Текст акцентов: `text-primary` или `text-[var(--color-primary)]`.
    *   Ховеры: `hover:bg-primary-hover` или `hover:bg-[var(--color-primary-hover)]`.
*   **Эстетика премиум-класса (Premium Visuals):**
    *   **Фоновые градиенты:** Используйте размытые цветные круги позади карточки ошибки (`bg-primary/10 blur-[120px] rounded-full absolute -z-10 animate-pulse`).
    *   **Стекломорфизм:** Основной контейнер с ошибкой должен иметь полупрозрачный размытый фон (`bg-white/80 backdrop-blur-xl border border-slate-100 dark:bg-slate-900/80 dark:border-slate-800`).
    *   **Микроанимации:** 
        *   Плавное появление контейнера (`motion.div` из `motion/react` или CSS-переходы).
        *   Вращение иконки перезагрузки при наведении на кнопку «Обновить» (`group-hover:rotate-180 transition-transform duration-500`).
    *   **Иконки:** Крупная, визуально приятная иконка в градиентной плашке по центру (например, `Search` для 404, `ServerCrash` или `AlertTriangle` для 500).

## 5. Адаптивность и мобильный UX (Mobile First)

Дизайн должен безупречно смотреться на экранах любых размеров.

*   **Отступы контейнера:** `p-4 sm:p-6` для внешнего контейнера, `p-8 sm:p-12` для карточки с ошибкой.
*   **Расположение кнопок:**
    *   На десктопе: Кнопки располагаются в ряд (`flex-row gap-4`).
    *   На мобильных устройствах (ширина `< 640px`): Кнопки выстраиваются вертикально во всю ширину (`flex-col gap-3 w-full`), чтобы по ним было легко кликать пальцем.
*   **Тач-зоны:** Высота интерактивных кнопок должна быть не менее `44px` (обычно `h-11` или `py-3.5`).
*   **Адаптивная типографика:**
    *   Крупный код ошибки (404/500): `text-5xl sm:text-7xl font-extrabold`.
    *   Заголовки: `text-xl sm:text-2xl font-bold`.
    *   Описание: `text-sm sm:text-base text-slate-500 max-w-md mx-auto text-balance`.

## 6. Чек-лист проверки реализации для ИИ-агента

Перед сдачей работы по страницам ошибок проверь:
1. [ ] Добавлена ли обертка макета (например, `DashboardLayout`) для сохранения сайдбаров на страницах ошибок верхнего уровня.
2. [ ] Все ли ссылки используют относительные роуты проекта (например, `Link` из `next/link` для предотвращения полной перезагрузки страницы при переходе на Главную).
3. [ ] Выстраиваются ли кнопки в вертикальный стек на экранах мобильных телефонов.
4. [ ] Отсутствуют ли жестко захардкоженные цвета бренда (цвета берутся из CSS-переменных темы проекта).
5. [ ] Добавлено ли логирование ошибок `console.error` или отправка отчетов в Sentry в `error.tsx` внутри `useEffect`.
6. [ ] Поддерживает ли кнопка «Обновить» реальный перезапуск через переданную функцию `reset()`.

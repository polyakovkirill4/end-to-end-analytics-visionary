# SaaS Интерактивная Финансовая Модель: 3 Отчета (МСФО)

Полное руководство по разработке, расчету и отображению интегрированной финансовой модели (Отчет о прибылях и убытках, Баланс, Отчет о движении денежных средств) в архитектуре веб-приложения (Frontend + Backend).

## ⚠️ КРИТИЧЕСКИЕ ПРИНЦИПЫ — Прочитать перед написанием кода

**Среда выполнения — Backend (Node.js/TS) vs Frontend (React):**
- **Никакого Excel:** Модель работает строго в веб-интерфейсе. Расчеты производятся функциями TypeScript. Данные хранятся в формате JSON в базе данных (Supabase).
- **Frontend (Интерактивность):** Пользователь меняет драйверы (Assumptions) через ползунки или инпуты. При изменении запускается пересчет локального стейта (Zustand/useReducer) для мгновенного отклика (Optimistic UI). 
- **Backend (Сохранение и ядро):** При сохранении сценария фронтенд отправляет финальные драйверы на сервер, который валидирует расчеты и сохраняет JSON-структуру в БД.

**Формулы вместо хардкода (не обсуждается):**
- Каждая прогнозируемая ячейка, агрегация, связь и промежуточный итог ДОЛЖНЫ быть результатом выполнения математической функции — никогда не хардкодьте рассчитанные значения.
- Единственные данные, которые могут быть статичными (хардкодом) — это (1) исторические фактические данные, (2) сами значения драйверов (допущений).

**Пошаговая проверка (как писать код для модели):**
1. **Подготовка структуры** → покажите пользователю какие вкладки/модули вы определили.
2. **Исторические данные** → покажите исторический блок, подтвердите соответствие значений.
3. **P&L (ОПиУ)** → запустите проверки промежуточных итогов, подтвердите перед переходом к Балансу.
4. **Баланс** → проверьте главное уравнение (Активы = Пассивы + Капитал), подтвердите перед переходом к ОДДС.
5. **Cash Flow (ОДДС)** → проверьте связку кэша (Кэш на конец периода в ОДДС = Кэш в Балансе), подтвердите перед финализацией.

## Структура Модели

### Идентификация организации модулей
В коде компоненты и данные должны быть организованы по модулям. Перед программированием продумайте структуру данных:

| Модуль (Компонент) | Содержимое |
|------------------|----------------------|
| IS, P&L, ОПиУ | Отчет о прибылях и убытках |
| BS, Баланс | Отчет о финансовом положении |
| CF, CFS, ОДДС | Отчет о движении денежных средств |
| WC, Оборотный капитал | График оборотного капитала |
| DA, D&A, Амортизация | График амортизации основных средств и НМА |
| Debt, Кредиты | График задолженности |
| Assumptions, Драйверы | Допущения и инпуты |
| Checks, Аудит | Дашборд проверки ошибок |

### Период прогнозирования
- По умолчанию модель должна прогнозировать на 5 лет вперед от последнего исторического года (или по месяцам на 1-3 года).
- Исторические (A - Actual) и прогнозные (E - Estimate) колонки должны визуально различаться.

## Сценарный Анализ (Scenario Analysis)

Используйте переключатель сценариев (Dropdown) в интерфейсе (Base / Upside / Downside). 

| Сценарий | Описание |
|----------|-------------|
| Базовый (Base Case) | Ожидания менеджмента или консенсус-прогноз |
| Оптимистичный (Upside) | Ускоренный рост, расширение маржинальности |
| Пессимистичный (Downside) | Замедление роста, сжатие маржи |

**Главные драйверы для сенситив-анализа:** Темп роста выручки, Валовая маржа (%), SG&A (%), DSO/DIO/DPO, CAPEX (%), Процентная ставка, Налоговая ставка.

## Заполнение Модели и Качество Данных (Quality Checks)

### Шаг 1: Правила ввода данных (Data Entry)
- Редактировать можно только инпуты (исторические данные и драйверы).
- Прогнозные формулы — строго readonly.
- Сохраняйте знаки (например, расходы могут быть отрицательными, если так принято в учетной политике).

### Шаг 2: Проверка по Отчетам (Quality Checks by Sheet)

**Проверки ОПиУ (IS):**
- Все статьи расходов корректно суммируются.
- Промежуточные итоги (Валовая прибыль, EBIT, EBT, Чистая прибыль) рассчитываются верно.
- Логика налогов корректна (учитывает убытки).

**Проверки Баланса (BS):**
- **Активы = Обязательства + Капитал** для КАЖДОГО периода (главная проверка).
- Кэш совпадает с остатком кэша из ОДДС.
- Нераспределенная прибыль (RE) переносится корректно.

**Проверки ОДДС (CF):**
- Чистая прибыль в начале ОДДС совпадает с Чистой прибылью из ОПиУ.
- Конечный кэш совпадает с кэшем в Балансе.

### Шаг 3: Перекрестные проверки (Integrity Checks)
| Проверка | Логика в коде | Ожидаемый результат |
|-------|---------|-----------------|
| Сверка Баланса | `Активы - Обязательства - Капитал` | `=== 0` |
| Сверка Кэша | `CF Конечный Кэш - BS Кэш` | `=== 0` |
| Сверка Чистой прибыли | `IS Чистая прибыль - CF Стартовая Чистая прибыль` | `=== 0` |

## Валидация и Аудит Модели (Audit)

### Обработка циклических зависимостей
Процентные расходы создают цикл: *Проценты -> Чистая прибыль -> Кэш -> Долг -> Проценты*.
В коде это решается ограничением итераций расчета: используйте цикл `while`, `max_iterations = 100`, `tolerance = 0.001`. 

### Быстрый Дебаг (Quick Debug Workflow)
При обнаружении ошибок в главном статусе Аудита:
1. Выявите, какая категория вернула ошибку (например, `Секция 2: Целостность Баланса`).
2. Проверьте источник данных (знаки в ОДДС, линковка).
3. Исправьте логику.
4. Убедитесь, что статус изменился на `✓ ALL CHECKS PASS`.

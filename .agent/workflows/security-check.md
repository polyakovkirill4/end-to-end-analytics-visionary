Выполни роль Senior Security Engineer. Проведи полный аудит безопасности текущего кода проекта (React + Supabase), опираясь на файл `rules.md` и лучшие практики OWASP.

Твоя задача — найти уязвимости, потенциальные утечки данных и логические дыры в безопасности.

### План проверки:

1.  **Supabase & RLS (Критично):**
    * Проверь, есть ли таблицы без включенного RLS (Row Level Security).
    * Проанализируй существующие политики RLS: не слишком ли они открыты (например, `true` для всех)?
    * Убедись, что данные одного пользователя/организации не доступны другому (tenant isolation).

2.  **Клиентская безопасность (React):**
    * Поиск использования `dangerouslySetInnerHTML`. Если есть — обосновано ли это?
    * Проверка защиты маршрутов (Protected Routes). Есть ли доступ к админским страницам без проверки сессии?
    * Проверка форм: везде ли используется валидация (Zod/React Hook Form) перед отправкой данных?

3.  **Финансы и логика:**
    * Проверь логику списания средств/баланса и оплаты. Нет ли возможности уйти в "минус" или изменить баланс на клиенте без проверки на сервере?
    * Убедись, что финансовые операции не используют Optimistic UI (согласно правилам).

4.  **Утечки данных:**
    * Сканирование кода на наличие хардкода API ключей (`service_role` ключей), паролей или чувствительных данных.
    * Проверка `.env` переменных (они должны иметь публичный префикс, например, NEXT_PUBLIC_ или аналогичный, только если безопасны для публичного доступа).

### Формат отчета:

Выведи результаты в виде таблицы:
| Статус | Файл/Компонент | Описание проблемы | Решение (Code Snippet) |
| :--- | :--- | :--- | :--- |
| 🔴 CRITICAL | `db_policies.sql` | RLS позволяет чтение всем (`anon`) | Добавить `auth.uid() = user_id` |
| 🟡 WARN | `PaymentForm.tsx` | Нет валидации суммы ввода | Добавить Zod схему `.min(1)` |
| 🟢 INFO | `Auth.tsx` | Хорошая практика | — |

В конце предложи **План исправлений**, отсортированный по приоритету.
